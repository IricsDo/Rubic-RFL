# Stage 2 ADI Policy/Value Training

The PyTorch ADI baseline trains a residual policy/value network on cube states
generated by applying moves backward from the solved cube. It is a research
checkpoint format for policy-guided search experiments and can be served by the
backend when the runtime has the Torch extra installed.

## Model Shape

`RubiksPolicyValueNet` consumes the same 324-value one-hot sticker feature used
by the NumPy baselines. It has an input projection, configurable residual
blocks, a policy head over the fixed 18-action move space, and a scalar value
head. The value target is normalized by the largest configured scramble depth;
checkpoint metadata stores `value_scale` so predictions can be converted back to
move-distance units.

## Report Shape

The report contains:

- `dataset`: record count, trainable policy records, depths, canonical depths,
  seed, and value scale.
- `model`: checkpoint path, model config, model version, and action ordering.
- `training`: hyperparameters plus per-iteration train and validation metrics.

ADI training now trains each iteration on all cumulative deduplicated records by
default. Pass `--train-on-latest-records` only when reproducing the older
latest-batch-only behavior. Iteration reports include `generated_records`,
`cumulative_records`, and `training_records` so the data flow is auditable.

## Backend Runtime

The backend can serve the `.pt` checkpoint through the same policy-guided search
path used for `.npz` policies:

```powershell
$env:RUBIC_RL_MODEL_PATH="checkpoints\torch-policy-value-adi-depth-1-10-regularized.pt"
$env:RUBIC_RL_POLICY_TYPE="torch"
$env:RUBIC_RL_POLICY_DEVICE="cpu"
$env:RUBIC_RL_MAX_STEPS="20"
$env:RUBIC_RL_SEARCH_WIDTH="10"
$env:RUBIC_RL_SEARCH_TOP_K="8"
cd backend
..\.venv\Scripts\uvicorn.exe app.main:app --reload
```

Use `RUBIC_RL_POLICY_DEVICE=cuda` only when the backend process has a working
CUDA PyTorch install. Replay packages record `policy_type` and `device` under
their `model` metadata for auditability.

## Depth 1-5 GPU Baseline

The first CUDA run used `torch 2.12.0+cu132` on an NVIDIA GeForce RTX 5070
Laptop GPU. It produced 4,312 deduplicated records and reached 61.6%
validation policy accuracy after 3 iterations.

Direct rollout comparison with the existing MLP baseline:

| Model | Overall solve rate | Depth 1 | Depth 2 | Depth 3 | Depth 4 | Depth 5 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Torch ADI | 64.4% | 100% | 100% | 67% | 37% | 18% |
| NumPy MLP | 52.4% | 100% | 95% | 47% | 16% | 4% |

Policy-guided beam search with `beam_width=5`, `top_k=5`, and
`max_depth=10` solved 82.4% overall for Torch ADI versus 68.0% for the MLP
baseline on the same seeded cases.

## Depth 1-10 GPU Baseline

The first depth 1-10 CUDA run used a 384-hidden-dimension model with 3 residual
blocks. It produced 29,955 deduplicated records. Training policy accuracy
reached 99.98%, but validation policy accuracy was 43.2%, so this run is useful
as a search baseline but shows overfitting.

Direct rollout with `max_steps=30`:

| Depth | Solve rate |
| ---: | ---: |
| 1 | 100% |
| 2 | 100% |
| 3 | 94% |
| 4 | 76% |
| 5 | 42% |
| 6 | 8% |
| 7 | 8% |
| 8 | 1% |
| 9 | 0% |
| 10 | 0% |

Search tuning on 50 seeded cases per depth:

| Search config | Overall solve rate | Avg expanded states | Avg duration ms |
| --- | ---: | ---: | ---: |
| Beam 5, top 5, max depth 20 | 50.4% | 52.4 | 35.8 |
| Beam 10, top 8, max depth 20 | 54.2% | 95.7 | 58.4 |
| Beam 20, top 10, max depth 25 | 56.6% | 221.7 | 133.3 |

The wider search adds cost faster than solve rate. The next training run should
improve policy generalization before increasing beam width again.

## Regularized Cumulative Depth 1-10 GPU Baseline

The regularized CUDA run trained on cumulative deduplicated records, used a
smaller 256-hidden-dimension model with 2 residual blocks, `dropout=0.1`,
`weight_decay=0.001`, and 2,000 samples per depth. It produced 57,625 records.
Final training policy accuracy was 62.4% and validation policy accuracy improved
to 49.5%, reducing the overfit gap from the first depth 1-10 run.

Direct rollout with `max_steps=30`:

| Depth | Solve rate |
| ---: | ---: |
| 1 | 100% |
| 2 | 100% |
| 3 | 98% |
| 4 | 90% |
| 5 | 62% |
| 6 | 23% |
| 7 | 12% |
| 8 | 4% |
| 9 | 2% |
| 10 | 0% |

Overall direct rollout solve rate improved from 42.9% to 49.1%.

Search tuning on 50 seeded cases per depth:

| Search config | Overall solve rate | Avg expanded states | Avg duration ms |
| --- | ---: | ---: | ---: |
| Beam 10, top 8, max depth 20 | 63.8% | 81.6 | 42.6 |
| Beam 20, top 10, max depth 25 | 66.4% | 182.7 | 96.3 |

Beam 10/top 8 is the better current operating point: it is 9.6 percentage
points better than the previous beam 10/top 8 result and faster on average. The
wider beam adds only 2.6 percentage points while more than doubling expanded
states and latency.
